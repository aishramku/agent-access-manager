How it works

AI agents don't police themselves. Agent Access Manager sits between the agent and the systems it wants to touch. Every request goes through the same checks before anything happens, and every decision is written to the audit log.

Least privilege

Each agent gets only the permissions it needs for its job, and nothing else. Anything not granted is denied by default.

Here: the Calendar Agent can move meetings but can't delete them. Turn a permission off and the next request is blocked.

Short-lived tokens

Agents carry a token that expires after one hour. An admin can revoke it at any moment, and access stops right away.

Here: revoke or rotate a token in the Agents tab and watch every request from that agent get blocked.
Maps toMicrosoft Entra IDOktaAzure Key Vault

Human approval

Risky or costly actions, like licensed software or shared data, wait for a person to sign off before the agent runs them.

Here: "Install Photoshop" and "Marketing folder" go to the Approval Queue instead of running.

Audit logging

Every decision is recorded: who asked, which agent, what action, the result, and why. Nothing happens off the record.

Here: the Audit Log tab, filterable by result and exportable to CSV.

v2 · Backend

With the Python backend connected (see the badge in the header), every decision runs on a FastAPI server: each agent carries a real signed JWT, revocation happens server-side, and the audit log and approval queue are stored in a database. Without a backend, the same rules run in your browser as a demo. Next: replace keyword routing with an AI agent that uses Claude tool calls, with every tool call checked by this gateway.
